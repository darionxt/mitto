# Changelog

What changes for callers in each version of mitto, newest first. The notes of each version's GitHub release hold its entry, and [releasing.md](docs/releasing.md#what-changes-for-callers) says how one is written.

## 0.3.0

A **Machine** also holds what a page reads of the computer and no client hint sends: its time zone, processors, work area, window, touch screen, contrast theme and the refresh rate of its display, and Windows' colour filter, which no page of Chrome 155 to 157 can read. A Page, whose API stays private, starts with them, with the rest of its Machine, and with its Persona's locale, user agent and user agent client hints, and its `navigator`, `screen`, window and `matchMedia()` give the same values that its Session sends, and its animation frame callbacks run at its display's refresh rate. What a Session sends does not change.

- [`Machine`](docs/api.md#machine) has 18 new fields, `refresh_rate`, `work_area_x`, `work_area_y`, `work_area_width`, `work_area_height`, `window_state`, `window_x`, `window_y`, `window_width`, `window_height`, `contrast_theme`, `inverted_colors`, `time_zone`, `processors`, `touch_points`, `audio_input`, `video_input` and `audio_output`, and [`Machine.draw()`](docs/api.md#machinedraw) takes each of them. A Machine that a caller makes needs every one, so a call of `Machine()` with only the values of mitto 0.2 raises a `TypeError`. `Machine.draw()` with those values draws the rest to fit them, a display that the table does not have too.
- A drawn Machine claims the time zone `America/New_York`, for the locale `en-US` of every Persona, logical processors from Firefox's statistics of processor cores, a refresh rate of 60 Hz in 84% of draws and 75 to 240 Hz in the rest, at the owner's weights in the shape of Firefox's telemetry, the taskbar at the bottom, a microphone in 70% of draws, a camera in 50% and something that plays sound in all, and no touch screen, contrast theme or colour filter, [as persona.md says](docs/persona.md#what-a-page-reads-beside-the-hints).
- A Machine refuses a refresh rate that is not a whole number of hertz from 24 to 1000, a time zone that Chrome on Windows never gives a page, such as `"Asia/Kolkata"` where Chrome gives `"Asia/Calcutta"`, a work area that is not on the display, a maximised window that is not the work area, a viewport larger than its window, and a contrast theme of the other Windows or with another colour scheme than it gives.
- A [`cookie_file`](docs/api.md#cookie_file) from mitto 0.2 loads with the new fields drawn from its Machine's seed, to fit what it has, or for a Machine with no seed worked out from what it has, so that it is the same Machine in every process. `close()` saves all of it, which mitto 0.2 refuses, so a caller that may go back to mitto 0.2 needs a copy of the file from before.
- [`Machine.named("mitto-0.1")`](docs/api.md#machinenamed) holds the new fields too: its work area, a maximised window, a refresh rate of 60 Hz, 8 processors, no touch screen, a microphone and speakers with no camera, and `America/New_York`.
- Each Persona's file, such as `mitto/personas/chrome_156_windows.json`, has a new key, `page_features`: the runtime-enabled features of Blink that a Page of the Persona turns on and off beside the Engine Release's, and V8's flags, with the version of the variations seed they were worked out with, and `deprecated_unload`, what the seed says of Chrome's deprecation of `unload` ([persona.md](docs/persona.md#what-a-page-of-each-persona-turns-on-and-off)). So a Page of an older Chrome Release lacks what that release did not ship yet, such as `CharacterData.prototype.afterHTML` in Chrome 155 and 156, and a Page of every Persona has what its seed switches, so none has `attributionSrc`, and no page of http or https has `unload` in `document.featurePolicy.allowedFeatures()`. What a Session sends does not change.
- [`RequestKind`](docs/api.md#requestkind) has eight new members, for what a document asks for beside its navigation, scripts, images and fetches: `STYLE`, `FONT`, `MODULE`, `XHR`, `WORKER`, `BEACON`, `IFRAME` and `FAVICON`, each with the lines, priority and fetch parameters that Windows Chrome sends for it, which each Persona's file holds under `kinds`. A request of the kind `worker` to another origin than its page's fails with `ERR_FAILED`, as Chrome's would, and one of the kind `iframe` gets the cookies of a frame of its page. Code that goes through every member of `RequestKind`, or every kind in a Persona's file, meets the new ones, and the kind `worker` has no `User-Agent` line, since `//net` adds it after `Referer`. What a Session sends for the four kinds of before does not change.
- A request of the kind `fetch`, `xhr`, `font` or `module` with an `initiator=` of another origin, which Chrome would send a CORS preflight for, such as a `PUT`, a `POST` with `json=` or one with a caller's own header, sends the preflight first, as Chrome does, and goes only if the server's answer allows it. Otherwise it raises a `RequestError` with `ERR_FAILED`, where mitto 0.2 sent it as it was. A Session keeps what a preflight allowed for as long as the server says, as Chrome does, so the next such request may go without one. A redirect that takes such a request to another origin waits for a preflight there too. A caller who wants the request without a preflight gives no `initiator=`, or one of the URL's origin. A Page's `fetch()` that needs a preflight goes after it, where it failed before.
- The wheel declares its licence as `Apache-2.0 AND CC-BY-SA-3.0 AND Unicode-3.0`. The list of time zones that a Machine takes, `mitto/time_zones.json`, comes from ICU's data, under the Unicode License v3, whose notice is in [`TIME_ZONES_NOTICE`](TIME_ZONES_NOTICE).

## 0.2.1

mitto installs on Windows on x64 too, from a `py3-none-win_amd64` wheel, with Python 3.12 or later, as on macOS on arm64 and Linux on x86_64. A Session presents Windows Chrome on every **Host**, on Windows as on macOS and Linux, with the same Personas and Machines. On macOS and Linux nothing changes for callers.

- The [asyncio API](docs/api.md#asyncio) works with both of Windows' event loops, `ProactorEventLoop` and `SelectorEventLoop`. Neither can watch the file descriptor that tells the loop of a Session's events on macOS and Linux, so on Windows a thread per Session waits for them in the native core, with the GIL released.
- On Windows a Session trusts, beside the Chrome Root Store, the roots that a user, an administrator or group policy has added to Windows' certificate stores, as Chrome there does ([`additional_trust_anchors=`](docs/api.md#additional_trust_anchors)).
- On Windows, as in Chrome there, a URL that starts with two slashes names a file on a network share, which a Session does not fetch: the request raises a `RequestError` with `ERR_UNKNOWN_URL_SCHEME`, where macOS and Linux give `ERR_INVALID_URL`.
- On Windows, `//net` asks Windows for a random source port for each QUIC connection, and from Windows 11 22H2 and on Windows Server 2025 for each TCP connection too, as Chrome does. Windows Server 2025 refuses about one such connect in 7,000, before it sends anything. A Session tries a refused connect again, with a new port, up to two more times, so its requests do not fail now and then with `ERR_NO_BUFFER_SPACE` or `ERR_ADDRESS_IN_USE`, as requests in Chrome there do. A server sees one ordinary connect ([#168](https://github.com/darionxt/mitto/issues/168)).

## 0.2.0

Each Session claims a **Machine** of its own: the memory, display, window, network, user settings and Windows version that its client hints say, once a server asks for them. In mitto 0.1, every Session of a Persona sent the same values. A server that does not ask for these hints sees no change.

- A Session draws its Machine from a table that ships with mitto, unless [`machine=`](docs/api.md#machine) gives one, and [`Session.machine`](docs/api.md#sessionmachine) is the one it claims. [`Machine.draw()`](docs/api.md#machinedraw) draws one with any value fixed, and the same one again from the same seed with the same table. Each run of the release routine refreshes the table, so a later version can draw another Machine from that seed. [`Machine.named("mitto-0.1")`](docs/api.md#machinenamed) is the one that every Session of mitto 0.1 claimed.
- `sec-ch-ua-platform-version` is no longer `"19.0.0"` for every Session: a Session sends `"10.0.0"` for a Machine on Windows 10, and `"19.0.0"` for one on Windows 11.
- `rtt` and `downlink` carry [Chrome's noise for each host](docs/persona.md#the-noise-on-rtt-and-downlink), so they change from host to host, and often between a navigation and the scripts, images and fetches of its page. A Session draws the noise when it opens, from its Machine's seed, so that the same Machine sends the same values again. A Machine with no seed, such as one a caller makes or `Machine.named("mitto-0.1")`, gets new noise each time a Session opens, as Chrome does each time it starts. So `Machine.named("mitto-0.1")` sends a `downlink` from 9 to 10, by host, where mitto 0.1 sent 10 to every host.
- A [`cookie_file`](docs/api.md#cookie_file), and a file that [`Cookies.save()`](docs/api.md#cookiessave) writes, holds the Session's Machine beside its cookies, as version 2 of the file, and a Session that opens with it claims that Machine. mitto 0.1 refuses a file of version 2, so a caller that may go back to mitto 0.1 needs a copy of the file from before. A file from mitto 0.1 loads as `Machine.named("mitto-0.1")`, and `close()` writes it again as version 2. A `machine=` that differs from the file's Machine raises a `ValueError`, and so does [`Cookies.load()`](docs/api.md#cookiesload) of a file of another Machine.
- The wheel declares its licence as `Apache-2.0 AND CC-BY-SA-3.0`. The table of Machines is under CC BY-SA 3.0, with the credits of its sources in [`MACHINE_TABLE_NOTICE`](MACHINE_TABLE_NOTICE), and the code stays under Apache-2.0.
